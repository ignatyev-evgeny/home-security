# home-security

Telegram-охрана дома на Frigate: кнопки «Поставить / Снять с охраны», алерты с
фото и видео при обнаружении человека, снимки со всех камер по запросу,
добавление и удаление камер из чата и внешний сторож, который замечает пропажу
связи с домом.

## Из чего состоит

**Дома (Ubuntu + Docker):**

```
камеры ──RTSP──► frigate ──MQTT──► guard ──► Telegram
                    │  ▲             │
              детекция  └──HTTP API──┘  (кадры, клипы, правка конфига)
                 OpenVINO
                 на iGPU
```

| Сервис | Роль |
|---|---|
| `frigate` | Декодирует потоки, детектит объекты, пишет события и клипы |
| `mosquitto` | MQTT-шина между Frigate и ботом, наружу не смотрит |
| `guard` | Бот: режим охраны, алерты, `/photo`, `/addcam`, heartbeat |

**Снаружи (VPS):** `watchdog` — принимает отчёт раз в минуту и бьёт тревогу,
когда отчёты пропали.

Детекцию движения делает Frigate по кадрам, а не сама камера, — встроенный
детектор Dahua в этой схеме не используется вообще.

## Почему так

**OpenVINO на встроенной графике.** i7-7700T — это Kaby Lake с HD Graphics 630:
хватает и на VAAPI-декодирование шести потоков, и на детекцию. Coral TPU
покупать не нужно.

**Детект и запись с одного основного потока.** Обе роли назначены одному входу:
это один процесс ffmpeg на камеру, а снимки уходят в полном разрешении. Замерено
на шести камерах 1080p: 27% восьми потоков, инференс 9 мс. Дешёвый вариант с
детектом по субпотоку описан ниже, в разделе «Качество снимков».

**ffmpeg на хост не ставится.** Он внутри образа Frigate; кадры и клипы `guard`
берёт по HTTP (`/api/<камера>/latest.jpg`, `/api/events/<id>/clip.mp4`).

**Порт 5000 не публикуется.** Это внутренний API Frigate без аутентификации —
им пользуется только `guard` по сети compose. Наружу открыт `8971`, где
аутентификация есть.

## Установка дома

```bash
cp .env.example .env
cp guard/config.example.yaml guard/config.yaml
cp frigate/config.example.yml frigate/config.yml
```

1. В `.env` — `BOT_TOKEN` от [@BotFather](https://t.me/BotFather) и
   `FRIGATE_RTSP_PASSWORD` (пароль админа камер).
2. В `frigate/config.yml` — переименуй камеры по комнатам (`cam_110` →
   `prihozhaya`): имя попадает в подпись к фото.
3. В `guard/config.yaml` — свой `chat_id` в `allowed_chat_ids`. Узнать его:
   запусти сервис, отправь боту `/start` — он ответит отказом и покажет id.
4. Если сторож ещё не развёрнут — поставь `heartbeat.enabled: false`.

```bash
docker compose up -d --build
docker compose logs -f frigate
```

Проверь в логах Frigate, что детектор поднялся на GPU и камеры дали поток.
Веб-интерфейс — `https://<сервер>:8971`, пароль админа Frigate печатает в лог при
первом запуске.

### Если `/dev/dri/renderD128` нет

Значит на хосте не установлены драйверы Intel:

```bash
sudo apt install intel-media-va-driver-non-free vainfo
```

Проверить: `ls -l /dev/dri/` — должен быть `renderD128`. Если устройства всё
равно нет, убери из `docker-compose.yml` секцию `devices` и замени детектор на
CPU (`type: cpu` в `detectors`) — для шести камер это заметная нагрузка,
но работать будет.

## Установка сторожа на внешнем сервере

```bash
scp -r watchdog/ user@vps:~/home-watchdog/
```

На сервере:

```bash
cp .env.example .env && openssl rand -hex 32
```

Впиши в `.env` тот же `BOT_TOKEN`, свой `CHAT_IDS` и сгенерированный
`AUTH_TOKEN`, затем:

```bash
docker compose up -d --build
```

Конфликта из-за общего токена нет: сторож только отправляет сообщения и
`getUpdates` не опрашивает.

Спрячь его за свой reverse proxy с HTTPS и пропиши адрес дома в `.env`:

```
WATCHDOG_URL=https://watchdog.example.com/heartbeat
WATCHDOG_TOKEN=<тот же AUTH_TOKEN>
```

Проверка снаружи:

```bash
curl -s https://watchdog.example.com/health
```

Отдаёт `last_seen`, `age_seconds`, `armed` и список упавших камер — этот же
эндпоинт можно скормить любому uptime-мониторингу.

## Что приходит в Telegram

| Событие | Сообщение |
|---|---|
| Человек в кадре под охраной | Фото сразу, дальше свежий кадр раз в 30 с, пока он не ушёл, и клип в конце |
| Камера перестала отдавать поток | Предупреждение, при возврате — «снова на связи» |
| Frigate упал | Предупреждение от локального бота и от сторожа |
| Дом пропал со связи | Тревога от сторожа с последним известным режимом |
| Кончается место под записи | Предупреждение от бота и от сторожа, при возврате — «в норме» |

Тревога о камерах приходит с двух сторон: локальный бот сообщает быстро, сторож
дублирует и остаётся единственным источником, если дома пропал интернет.

### Почему кадры досылаются

Frigate отдаёт клип целиком и только после того, как объект покинул кадр. Если
человек пробыл в комнате десять минут, клип будет десятиминутным и придёт через
десять минут — а крупный файл ещё и упрётся в лимит Telegram на бота в 50 МБ.

Поэтому фото приходит сразу, а затем, пока событие живо, раз в
`followup_seconds` досылается свежий кадр с подписью «всё ещё в кадре».
Досылка прекращается, когда человек ушёл, когда дом сняли с охраны или когда
исчерпан `followup_max` — предохранитель на случай, если человек сел и замер, а
событие тянется часами. По исчерпании приходит отдельное уведомление, чтобы
тишина не читалась как «всё закончилось».

### Качество снимков

Кадры берутся из **detect-потока** — того, что Frigate анализирует. Его
разрешение и есть потолок качества снимков: `snapshot_height` выше него только
растянет картинку и раздует файл, поэтому по умолчанию стоит `0` — отдавать как
есть.

Поэтому detect назначен на основной поток камеры, тем же входом, что и запись.
На камерах Dahua K200WP разница получается такая:

| detect | разрешение | снимок (q95) |
|---|---|---|
| субпоток `subtype=1` | 704×576 | ~70 КБ |
| основной `subtype=0` | 1920×1080 | ~300–480 КБ |

Замер на шести камерах: CPU вырос со 13% до 27% восьми потоков, инференс 9 мс.
Побочно исчезло отставание обработки от захвата, которое было на субпотоке
у двух камер.

Если железо слабее, detect можно вернуть на субпоток — разнести роли по двум
входам в `frigate/config.yml` и поставить `detect_path` с `subtype=1` в
`guard/config.yaml`, чтобы `/addcam` делал так же. Когда пути записи и детекта
совпадают, `/addcam` создаёт один вход с двумя ролями, а когда различаются —
два отдельных.

Отдельная деталь: у камеры основной поток может быть настроен ниже её
максимума. В нашем случае пять камер отдают 1080p, а одна — 720p; лечится
в веб-интерфейсе самой камеры.

### Когда клип не влезает в Telegram

У ботов Telegram потолок на файл — 50 МБ, и длинное событие в него не помещается.
Такой клип даже не пытаемся отправлять: вместо него приходит сообщение с
размером и **прямой ссылкой** на запись во Frigate.

Ссылки строятся из `frigate.public_url` — адреса, по которому ты достаёшь
Frigate с телефона, обычно через VPN:

```yaml
frigate:
  public_url: "https://192.168.1.50:8971"
```

Схема именно **https**: на 8971 Frigate поднимает TLS с самоподписанным
сертификатом, а на `http://` тот же порт отвечает `400`. Браузер один раз
предупредит о сертификате — это ожидаемо. Первый переход попросит логин
Frigate, дальше сессия запомнится. Если `public_url` не задан, вместо ссылки
придёт подсказка это сделать — битых ссылок бот не шлёт.

Те же ссылки прикладываются, когда клип не появился вовсе или Telegram отверг
файл: посмотреть запись всё равно надо. Остальные ошибки тоже не молчат —
причина приходит текстом, включая обрыв камеры во время досылки кадров.

### Камеры не-Dahua

`/addcam` собирает ссылку по шаблону из `camera_defaults`, то есть умеет только
камеры с адресацией как у Dahua. Камеру другого вендора добавляют руками —
но сначала надо узнать её RTSP-ссылку, а гадать по спискам форматов долго.
Надёжнее спросить саму камеру по ONVIF.

Сначала посмотри, что за устройство: открытые порты уже многое говорят.
`8899` и `34567` — почерк XiongMai (iCSee/XMEye), `80`+`554` без ONVIF —
скорее всего Dahua или Hikvision.

```bash
for p in 554 8000 8899 34567 80; do nc -z -G 3 <ip> $p && echo "порт $p открыт"; done
```

Дальше ONVIF без авторизации подтвердит, что он вообще есть:

```bash
curl -s -m 10 -X POST "http://<ip>:8899/onvif/device_service" -H 'Content-Type: application/soap+xml' -d '<?xml version="1.0"?><s:Envelope xmlns:s="http://www.w3.org/2003/05/soap-envelope"><s:Body><GetSystemDateAndTime xmlns="http://www.onvif.org/ver10/device/wsdl"/></s:Body></s:Envelope>'
```

Если ответ пришёл — модель, разрешения и точные ссылки на потоки достаются
запросами `GetDeviceInformation`, `GetProfiles` и `GetStreamUri` с
WS-Security-подписью. Готовый скрипт лежит в [tools/onvif_probe.py](tools/onvif_probe.py):

```bash
docker compose exec -T guard python - < tools/onvif_probe.py
```

Он спрашивает камеру по адресу из `CAM_PROBE_HOST` и печатает ссылки на все
профили. **Учти**: многие камеры возвращают URI с логином и паролем в открытом
виде — не пересылай вывод как есть.

Полученную ссылку вставь в `frigate/config.yml` вручную, заменив пароль на
`{FRIGATE_RTSP_PASSWORD}`, — пример есть в шаблоне (`cam_117`, XiongMai).

### Собаки и прочие ложные срабатывания

Тревоги шлёт бот, а не Frigate: в `alerts.labels` перечислено, что считать
поводом. Поэтому объект удобно **трекать, но не алертить** — так он виден в UI
Frigate и понятно, что происходит перед камерой, но телефон молчит:

```yaml
# frigate/config.yml — у конкретной камеры
    objects:
      track: [person, dog]
      filters:
        person:
          min_score: 0.7
```

```yaml
# guard/config.yaml — общее
alerts:
  labels: [person]
```

Если собаку всё-таки принимает за человека, помогает `max_ratio` в фильтре
`person`: у стоящего человека рамка узкая и высокая (ratio ≈ 0.3–0.5), у собаки
широкая (≈ 1.2–2.0). Значение подбирают по реальным событиям в UI Frigate, а не
наугад.

### Место под записи

Заполненный раздел — тихий отказ: Frigate просто перестаёт писать, и
обнаруживается это ровно тогда, когда запись понадобилась. Поэтому бот следит
за свободным местом сам и предупреждает заранее, на пороге `alerts.min_free_gb`
(по умолчанию 20 ГБ, `0` отключает). Текущее значение видно в `/status` и
`/cams`, а также уходит в heartbeat — сторож продублирует тревогу снаружи.

Цифры берутся из `/api/stats` Frigate и относятся ко **всей файловой системе**,
а не только к его файлам. Это осознанно: раздел обычно общий с другими
сервисами, и переполнить его может кто угодно, а запись встанет у нас.

Сколько занимают записи, зависит от количества движения. Ориентир с семи камер
(шесть 1080p и одна 5 МП): порядка 1.4 ГБ в час сырого потока, но раз в час
Frigate удаляет всё, что не попало в события, так что оседает заметно меньше.
Срок хранения задаётся в `frigate/config.yml` — `record.alerts.retain.days` и
`record.detections.retain.days`. Детекции обычно можно держать меньше тревог:
это весь шум подряд.

### Почему падение камеры подтверждается не сразу

Упавшей камера считается только после трёх подряд неудачных опросов (90 секунд).
Frigate штатно перезапускает ffmpeg, и в этот момент поток на пару секунд
пропадает — без такого порога каждый рестарт давал бы ложную тревогу.
В `/cams` при этом видно мгновенное состояние, без задержки.

## Команды

| Команда | Что делает |
|---|---|
| `/start`, `/status` | Панель с кнопками и сводка |
| `/photo` | Текущий кадр со всех камер одной пачкой |
| `/cams` | Список камер: fps, детекция, кто не на связи |
| `/addcam имя ip` | Проверяет камеру и добавляет её во Frigate |
| `/delcam имя` | Удаляет камеру (с подтверждением) |
| `/arm`, `/disarm` | То же, что кнопки |

`/addcam` сначала стучится к камере по `magicBox.cgi` и добавляет её в конфиг,
только если она ответила: иначе о неверном IP или пароле стало бы известно
лишь после перезапуска Frigate со сломанным конфигом. Правка идёт через
`/api/config/save`, то есть Frigate сам валидирует результат.

Обе команды перезапускают Frigate — потоки прерываются примерно на минуту.

## Настройка под себя

| Где | Параметр | Смысл |
|---|---|---|
| `frigate/config.yml` | `objects.filters.person.min_score` | Порог детекции. Много ложных — поднять |
| `frigate/config.yml` | `detect.fps` | Кадров в секунду на анализ. Больше — точнее и дороже |
| `frigate/config.yml` | `record.alerts.retain.days` | Сколько хранить записи |
| `guard/config.yaml` | `alerts.labels` | Кого считать тревогой (`person`, `car`, `dog`…) |
| `guard/config.yaml` | `alerts.cooldown_seconds` | Пауза между алертами одной камеры |
| `guard/config.yaml` | `alerts.followup_seconds` | Как часто досылать кадр, пока человек в кадре. `0` — не досылать |
| `guard/config.yaml` | `alerts.followup_max` | Сколько досылок максимум на одно событие |
| `guard/config.yaml` | `frigate.public_url` | Адрес Frigate для ссылок на крупные клипы (нужен VPN) |
| `guard/config.yaml` | `alerts.snapshot_height` | Высота снимков. `0` — родное разрешение detect-потока |
| `guard/config.yaml` | `alerts.snapshot_quality` | Качество JPEG, 1–100 |
| `guard/config.yaml` | `alerts.send_clip` | Выключить, если хватает фото |
| `guard/config.yaml` | `alerts.min_free_gb` | Порог свободного места, ГБ. `0` — не следить |
| `watchdog/.env` | `STALE_SECONDS` | Через сколько молчания бить тревогу |

Чтобы реагировать не на любого человека, а на зоны (двор, но не улица за
забором), в UI Frigate есть маски и `zones` — тогда в `alerts.labels` можно
оставить `person`, а лишнее отсечь геометрией.

## Безопасность

- Камеры K200-серии (~2016 г.) обновлений не получают: не пробрасывай к ним
  порты и не включай Easy4ip. Лучше — отдельный VLAN без выхода в интернет,
  доступ только с сервера с Frigate.
- `allowed_chat_ids` обязателен: без whitelist снять дом с охраны сможет любой,
  кто найдёт бота.
- `AUTH_TOKEN` у сторожа обязателен, иначе кто угодно сможет слать поддельные
  отчёты «всё хорошо» и глушить тревогу.
- `.env`, `guard/config.yaml` и `frigate/config.yml` в `.gitignore` — в них
  пароли.
